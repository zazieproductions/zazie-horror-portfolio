# Testing and verification

All commands below exist in `package.json` (verified 2026-10-29).

| Command | Proves |
|---|---|
| `npm run typecheck` | `src/` type-checks under strict TS (`tsc --noEmit`) |
| `npm test` | 14 `node --test` files in `tools/` (routing, headers, forms-adjacent behaviour, players, SEO semantics, …) |
| `npm run build` | Full pipeline incl. `verify`, `check:headers`, `check:links`, `check:forms`, sitemap/redirect/alias/coverage gates |
| `npm run verify` | Structural/content/schema audit of prerendered pages (`scripts/verify.mjs`) |
| `npm run check:links` | Every internal link + `#fragment` resolves the way the host would resolve it |
| `npm run check:forms` | Every form control in served HTML carries an `id` or `name` |
| `npm run check:headers` | `_headers` matches `tools/headers.mjs`; one cache lifetime per path |
| `npm run check:docs` | Local Markdown links in `README.md` + `docs/` resolve (this overhaul) |
| `npm run lint:slop` | aislop quality gate (score floor + baseline in `.aislop/`) |
| `npm run seo:coverage` | Per-URL word count / inbound links / duplication report |
| `node tools/resolve-conflicts.mjs --base origin/main --dry-run` | Merge-base dry run: shows which conflicts the build can resolve and which need a human (`tools/resolve-conflicts.test.mjs` covers the decision logic) |

## Known baseline (2026-10-29, this branch, Node 22)

- `npm ci` — pass. `npm run typecheck` — pass.
- `npm test` on a **fresh clone without `build/`** — 66/68 pass; `tools/geo.test.mjs`
  and `tools/inquiry.test.mjs` fail with `ERR_MODULE_NOT_FOUND: build/data/*.js`
  because they import `tsc` output. Run `npm run build` (or `npx tsc`) first.
  This is a pre-existing ordering quirk, documented here rather than hidden.
- After `npm run build` — 81/82 pass; `tools/mobile-ux.test.mjs`
  ("mobile UX stylesheet … survives regeneration") fails in this environment
  alongside bundle rehash churn (see
  [known limitations](../project/known-limitations.md)). Not introduced by
  documentation changes; do not "fix" it by committing unrelated regenerated output.
- `npm run verify`, `check:forms`, `check:headers` — pass on the committed tree.
- `npm run check:links` on the **committed tree without a prior build** — FAILS
  (pre-existing at HEAD): committed HTML references `/inquiry-d8cba1f7.css`,
  which is only (re)generated by `npm run build` and is absent from the tree.
  After a build it passes. Recorded here so nobody "fixes" it by committing
  unrelated regenerated churn.

> [!IMPORTANT]
> Never represent an unexecuted check as passing. Record command, date and
> result — as above — especially in PR descriptions.
